# אתר הסטודיו של AMDIR (אב טיפוס)

אתר סטטי לסטודיו: עבודות, שירותים, מוצר (Event Pro Studio) ויצירת קשר. בעברית, מימין לשמאל.
הכול כאן מקומי. שום דבר לא פורסם, לא נדחף ל-GitHub ולא חובר לשירות חיצוני.

- **Astro 7** (פלט סטטי, בלי שרת) + TypeScript במצב strictest
- **Content Collections** עם סכמות Zod: `src/content.config.ts`
- **Keystatic** לעריכת תוכן בממשק, רק בזמן פיתוח: `http://127.0.0.1:4321/keystatic`
- CSS רגיל עם משתנים, בלי Tailwind. פונטים מאוחסנים באתר עצמו (@fontsource), בלי Google Fonts.

## הרצה

צריך Node 22.22 ומעלה.

```bash
npm install
npm run dev            # פיתוח, כולל Keystatic ב-/keystatic. חומר זמני מוצג תמיד.
npm run check          # בדיקת טיפוסים (astro check)
npm run build          # בניית ייצור ל-dist/  (בלי חומר זמני, בלי מתג סקירה)
npm run build:review   # בניית סקירה ל-dist-review/ (עם חומר זמני ומתג כיווני עיצוב)
npm run preview        # צפייה בבנייה האחרונה
npm run qa             # צילומי מסך, גלישה אופקית, axe ובדיקות פונקציונליות על dist-review
npm run serve -- dist 4321   # שרת סטטי מקומי לבדיקה של תיקיית בנייה
```

הערה: Astro נעול על 7.4.1, כי 7.4.2 דורש Node 22.23.4 ומעלה. עם Node חדש יותר אפשר לעדכן.
Lighthouse (מובייל) מריצים כך: `CHROME_PATH=<נתיב לכרום> npx lighthouse http://127.0.0.1:4321/`.

### הגדרות (קובץ `.env`, ראו `.env.example`)

| משתנה | מה הוא עושה |
|---|---|
| `PUBLIC_SITE_URL` | הדומיין הסופי. משמש לקישורים קנוניים, sitemap ו-OpenGraph. **[להשלמה]** |
| `PUBLIC_SHOW_PLACEHOLDERS` | `true` = מציג גם פריטים שמסומנים כחומר זמני. בייצור: `false`. |
| `PUBLIC_REVIEW_MODE` | `true` = מציג פס "מצב סקירה" להחלפה בין שני כיווני העיצוב. לעולם לא בייצור. |
| `PUBLIC_BASE_PATH` | אם האתר יושב בתת-תיקייה, למשל `/review/`. ברירת מחדל `/`. |
| `PUBLIC_LEAD_ENDPOINT` | כתובת לשליחת טפסים. ריק = הטופס לא מחובר (ראו למטה). |

בניית סקירה לתת-תיקייה: `REVIEW_BASE=/review/ npm run build:review`. כל הקישורים באתר עוברים דרך `url()` ב-`src/lib/url.ts`, ולכן עובדים גם בתת-תיקייה.

## שני כיווני העיצוב

אותו HTML, שתי ערכות עיצוב, לפי `data-direction` על תגית `<html>`:

- **א׳ במה** (`stage`): כהה, Karantina לכותרות, Heebo לטקסט, מגנטה כצבע הדגשה.
- **ב׳ אינדקס** (`index`): בהיר וכהה לפי המכשיר, IBM Plex Sans Hebrew ו-IBM Plex Mono, כתום כצבע הדגשה.

הכיוון שנבחר נקבע ב"הגדרות האתר" (שדה כיוון עיצוב). כל הצבעים והגדלים נמצאים ב-`src/styles/tokens.css`.
בבניית סקירה יש פס קטן בתחתית המסך להחלפה. אפשר גם לשתף קישור ישיר: `?direction=index&theme=dark`.

## איך מוסיפים תוכן

### דרך Keystatic (מומלץ)

1. `npm run dev`
2. פותחים `http://127.0.0.1:4321/keystatic`
3. **עבודות**: "עבודה חדשה". ממלאים כותרת, סוג, תחומים, שנה, המטרה, מה נוצר, קרדיטים, כלים, תמונת פתיחה + טקסט חלופי.
   - **קליפ**: תחום "קליפים", שם האמן בשדה "אמן" (הכותרת תוצג "אמן - שיר"). בסרטון בוחרים Bunny, Vimeo, YouTube או קובץ, ומוסיפים קובץ כתוביות בעברית אם יש. מסמנים "המוזיקה מורשית לשימוש".
   - **אתר**: תחום "אתרים", ממלאים "קישור לאתר", ומעלים צילומי מסך לגלריה (כל תמונה עם טקסט חלופי).
   - **תמונה או סדרת תמונות**: תחום "תמונות" (ו-AI אם רלוונטי), התמונות בגלריה.
   - אם נעשה שימוש ב-AI: מסמנים "נעשה שימוש ב-AI" וכותבים משפט קצר מה נעשה. זה יופיע כקרדיט אחד מתוך כמה.
4. **שירותים** ו**מוצרים**: אותו דבר, בטפסים שלהם.
5. השינויים נשמרים כקבצים בתוך הפרויקט. אחרי בדיקה עושים commit ב-git.

### דרך קבצים

- עבודה = קובץ YAML ב-`src/content/works/<slug>.yaml`. הכי פשוט: להעתיק קובץ קיים ולשנות.
- תמונות: `src/assets/works/<slug>/...`. בקובץ ה-YAML הנתיב יחסי, למשל `../../assets/works/<slug>/poster.jpg`.
- וידאו בקובץ: לשים ב-`public/media/` ולכתוב `id: /media/שם.mp4`.
- שירותים: `src/content/services/`, מוצרים: `src/content/products/`, הגדרות: `src/content/settings/site.yaml`.
- `npm run check` יגיד מיד אם חסר שדה חובה (למשל טקסט חלופי לתמונה).

## חומר זמני והרשאות

- **חומר זמני** (`placeholder: true`): מוצג עם תג "חומר זמני". בבניית ייצור (`npm run build`) הוא **לא נכלל**, אלא אם `PUBLIC_SHOW_PLACEHOLDERS=true`. כרגע כל 6 העבודות, 2 השירותים והמוצר זמניים, ולכן בבניית ייצור רואים מצבים ריקים מעוצבים.
- **עבודת לקוח** (`type: client`) נכללת רק אם `permissionToShow: true`. בלי אישור היא לא נבנית בכלל, והבנייה מדפיסה אזהרה.
- **מוזיקה בקליפים**: קליפ של לקוח או אישי בלי `musicLicensed: true` נכלל, אבל הבנייה מדפיסה אזהרה. (כרגע יש אזהרה מכוונת על "קליפ קצר לרשתות", לדוגמה.)
- **תוצאה** (`outcome`) מוצגת רק אם יש לה גם `source`. בלי מקור, לא מוצגת.
- **מחירים**: אין מחירים באתר. אם ימולא מחיר לשירות, הוא יוצג רק יחד עם "+מע״מ" או "כולל מע״מ".
- כל הכללים האלה נמצאים במקום אחד: `src/lib/content.ts`.

## טופס יצירת קשר

הטופס נגיש (תווית מעל, שגיאה מתחת, מעבר לשדה הראשון לתיקון), עם הודעת יידוע לפני כפתור השליחה, תיבת הסכמה למדיניות הפרטיות (חובה), ותיבה **נפרדת ולא מסומנת מראש** לקבלת עדכונים.

כרגע אין שרת, ולכן הטופס **לא מציג הצלחה**. הוא מציג "הטופס עדיין לא מחובר. בינתיים אפשר לפנות בוואטסאפ", ומה שהוקלד נשאר בטופס.

**חיבור בעתיד** (Supabase Edge Function, Resend וכו׳) נעשה במקום אחד: `src/lib/lead.ts`.
מגדירים `PUBLIC_LEAD_ENDPOINT`, והשרת צריך לבדוק את אותם שדות, לשמור, ולהחזיר `{ "ok": true }` רק אחרי שהשמירה הצליחה. צריך גם להוסיף את הכתובת ל-`connect-src` ב-CSP.

## Keystatic בפיתוח בלבד

Keystatic צריך נתיבי שרת, ולכן `astro.config.mjs` מוסיף את React, את Keystatic ואת מתאם Node **רק** כשמריצים `astro dev`. בבנייה (`astro build`) האתר נשאר סטטי לגמרי. לעריכה בענן (Keystatic Cloud או GitHub) יידרש בעתיד אחסון עם שרת או מצב GitHub, וזו החלטה נפרדת.

## וידאו, פרטיות ו-CSP

רכיב `VideoFacade` מציג רק תמונת פתיחה מקומית. הנגן (Bunny, Vimeo, YouTube בגרסת nocookie, או `<video>`) נוצר רק אחרי לחיצה, עם קול. לפני הלחיצה אין אף בקשה לשרת חיצוני. כשקובעים CSP באחסון:
- `frame-src` לספק שנבחר: `iframe.mediadelivery.net` / `player.vimeo.com` / `www.youtube-nocookie.com`
- `media-src 'self'` (או ה-CDN של הקבצים)

אין באתר אנליטיקס. אם יתווסף, רק אחרי הסכמה מפורשת (לא "המשך גלישה").
